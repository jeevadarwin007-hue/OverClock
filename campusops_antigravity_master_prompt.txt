SECTION 1: THE CORE ARCHITECTURAL INVARIANTS (NON-NEGOTIABLE)
================================================================================

1. NEURO-SYMBOLIC DIVIDE:
   - AI is strictly restricted to: Unstructured NLP extraction, stateful slot clarification,
     semantic similarity assist, and natural-language briefing summaries.
   - Deterministic Backend Logic handles: Permissions (RBAC/SoD), room scheduling, double-booking
     prevention, technician dispatch scoring, inventory reservations, approval checks, state transitions,
     and SLA math.
   - AI MUST NEVER decide who gets assigned, which room is booked, whether stock is sufficient,
     or whether an approval passes.

2. ZERO EXTERNAL I/O IN OPERATIONAL DATABASE TRANSACTIONS:
   - Ingestion follows a strict 4-Phase pipeline:
     Phase 1: Atomic Event Claim with Worker Leases (DB Tx #1, < 3ms).
     Phase 2: Lock-Free LLM Extraction & Read Resolution (Out-of-Transaction, 2.5s timeout, regex fallback).
     Phase 3: Bounded Atomic Operational Commit (DB Tx #2, < 15ms).
     Phase 4: Asynchronous Outbox Worker & Spatial Streaming.
   - Never hold database locks while waiting for an LLM API call, human approval, or SMTP/webhook delivery.

3. POSTGRESQL KERNEL INVARIANTS:
   - Room Double-Booking: Enforced via `btree_gist` index over `TSTZRANGE` with `EXCLUDE USING gist`.
   - Inventory Conservation: `CHECK (physical_on_hand_qty = available_qty + reserved_qty)` backed by an
     append-only `inventory_movements` ledger.
   - Directed Acyclic Graph (DAG): Cycle detection enforced via a recursive `BEFORE INSERT OR UPDATE` trigger.
   - Approval Integrity: SHA-256 canonical snapshot verification. Any mutation to work order cost, scope,
     or parts automatically flips status to `INVALIDATED_BY_CHANGE`.
   - Work Order FSM: State transitions and actor roles enforced via a reference matrix table and trigger.
   - Immutable Audit: `audit_logs` table has a trigger raising an exception on UPDATE, DELETE, or TRUNCATE.

4. 2.5D EXTRUDED MAP & SPATIAL TWIN:
   - Do NOT build an 80MB Three.js/Blender 3D mesh.
   - Build a 2.5D extruded vector map using MapLibre GL JS (`react-map-gl/maplibre`) using GeoJSON
     building footprints extruded by `height_m = floors * 3.5m`.
   - Building colors must be data-driven via GPU paint expressions hooked to `/api/v1/campus/map-status`.
   - Full 2D fallback when camera pitch is 0°.

DECLARE v_role user_role;
BEGIN

END;

CREATE OR REPLACE FUNCTION trg_fn_prevent_dag_cycles()
RETURNS TRIGGER AS $$
DECLARE v_is_reachable BOOLEAN;
BEGIN
    PERFORM pg_advisory_xact_lock(hashtext(NEW.dependency_domain::text));

    WITH RECURSIVE reachability AS (
        SELECT child_node_id AS current_id, 1 AS depth
        FROM node_dependencies
        WHERE parent_node_id = NEW.child_node_id AND dependency_domain = NEW.dependency_domain
        UNION
        SELECT nd.child_node_id, r.depth + 1
        FROM node_dependencies nd
        JOIN reachability r ON nd.parent_node_id = r.current_id
        WHERE nd.dependency_domain = NEW.dependency_domain AND r.depth < 12
    )
    SELECT EXISTS (SELECT 1 FROM reachability WHERE current_id = NEW.parent_node_id) INTO v_is_reachable;

    IF v_is_reachable THEN
        RAISE EXCEPTION 'DAG Cycle Violation: Adding edge % -> % creates a loop in domain %', 
            NEW.parent_node_id, NEW.child_node_id, NEW.dependency_domain;
    END IF;

    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_enforce_dag_acyclic
BEFORE INSERT OR UPDATE ON node_dependencies
FOR EACH ROW EXECUTE FUNCTION trg_fn_prevent_dag_cycles();

CREATE OR REPLACE FUNCTION trg_fn_enforce_inventory_ledger()
RETURNS TRIGGER AS $$
BEGIN
    IF (NEW.physical_on_hand_qty <> OLD.physical_on_hand_qty) 
       OR (NEW.available_qty <> OLD.available_qty) 
       OR (NEW.reserved_qty <> OLD.reserved_qty) THEN
        IF NOT EXISTS (
            SELECT 1 FROM inventory_movements 
            WHERE part_id = NEW.id 
              AND delta_physical = (NEW.physical_on_hand_qty - OLD.physical_on_hand_qty)
              AND delta_available = (NEW.available_qty - OLD.available_qty)
              AND delta_reserved = (NEW.reserved_qty - OLD.reserved_qty)
              AND created_at >= NOW() - INTERVAL '5 seconds'
        ) THEN
            RAISE EXCEPTION 'Inventory Security Violation: Direct modification of balances without movement ledger entry is forbidden.';
        END IF;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_inventory_tamper_guard
BEFORE UPDATE ON inventory_parts
FOR EACH ROW EXECUTE FUNCTION trg_fn_enforce_inventory_ledger();

CREATE OR REPLACE FUNCTION trg_fn_enforce_wo_fsm()
RETURNS TRIGGER AS $$
DECLARE
    v_role user_role;
    v_allowed BOOLEAN;
BEGIN
    IF OLD.state = NEW.state THEN
        RETURN NEW;
    END IF;

    v_role := get_current_actor_role();

    SELECT EXISTS (
        SELECT 1 FROM fsm_state_transitions
        WHERE from_state = OLD.state 
          AND to_state = NEW.state 
          AND v_role = ANY(allowed_roles)
    ) INTO v_allowed;

    IF NOT v_allowed THEN
        RAISE EXCEPTION 'FSM Violation: Role % is not permitted to transition work order from % to %',
            v_role, OLD.state, NEW.state;
    END IF;

    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_work_order_fsm_enforcement
BEFORE UPDATE OF state ON work_orders
FOR EACH ROW EXECUTE FUNCTION trg_fn_enforce_wo_fsm();

CREATE OR REPLACE FUNCTION fn_compute_canonical_wo_snapshot(p_wo_id UUID)
RETURNS VARCHAR AS $$
DECLARE
    v_canonical_text TEXT;
    v_wo RECORD;
    v_parts_json JSONB;
BEGIN
    SELECT target_node_id, category, estimated_cost, department_id 
    INTO v_wo FROM work_orders WHERE id = p_wo_id;

    SELECT COALESCE(jsonb_agg(
        jsonb_build_object('part_id', part_id, 'qty', requested_qty, 'cost', locked_unit_cost)
        ORDER BY part_id
    ), '[]'::jsonb) INTO v_parts_json
    FROM part_reservations WHERE work_order_id = p_wo_id;

    v_canonical_text := format('node:%s|cat:%s|cost:%s|dept:%s|parts:%s',
        v_wo.target_node_id, v_wo.category, v_wo.estimated_cost, v_wo.department_id, v_parts_json);

    RETURN encode(digest(v_canonical_text, 'sha256'), 'hex');
END;
$$ LANGUAGE plpgsql STABLE;

CREATE OR REPLACE FUNCTION trg_fn_invalidate_approval_on_scope_change()
RETURNS TRIGGER AS $$
DECLARE
    v_wo_id UUID;
    v_current_hash VARCHAR(64);
    v_approval RECORD;
BEGIN
    IF TG_TABLE_NAME = 'work_orders' THEN
        v_wo_id := NEW.id;
    ELSIF TG_TABLE_NAME = 'part_reservations' THEN
        v_wo_id := COALESCE(NEW.work_order_id, OLD.work_order_id);
    END IF;

    v_current_hash := fn_compute_canonical_wo_snapshot(v_wo_id);

    FOR v_approval IN 
        SELECT id, snapshot_hash FROM approvals 
        WHERE work_order_id = v_wo_id AND status IN ('PENDING', 'APPROVED')
    LOOP
        IF v_approval.snapshot_hash <> v_current_hash THEN
            UPDATE approvals 
            SET status = 'INVALIDATED_BY_CHANGE',
                invalidation_reason = 'Scope mutated after approval grant.',
                decided_at = NOW()
            WHERE id = v_approval.id;

            UPDATE work_orders 
            SET state = 'PENDING_APPROVAL' 
            WHERE id = v_wo_id AND state IN ('APPROVED_READY', 'ASSIGNED', 'IN_PROGRESS');
        END IF;
    END LOOP;

    RETURN NULL;
END;
$$ LANGUAGE plpgsql;

        NOT isempty(time_slot) AND

    CONSTRAINT prevent_room_double_booking
    EXCLUDE USING gist (
        room_node_id WITH =,
        time_slot WITH &&
    ) WHERE (status IN ('CONFIRMED', 'CONTINGENCY_HOLD', 'MAINTENANCE_BLOCK'))

CREATE OR REPLACE FUNCTION trg_fn_validate_room_operational()
RETURNS TRIGGER AS $$
DECLARE v_is_op BOOLEAN;
BEGIN
    SELECT is_operational INTO v_is_op FROM campus_nodes WHERE id = NEW.room_node_id;
    IF NOT v_is_op AND NEW.booking_type IN ('CLASS', 'EXAM', 'CONTINGENCY_HOLD') THEN
        RAISE EXCEPTION 'Room Booking Violation: Room % is non-operational.', NEW.room_node_id;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 11. LIVE ANALYTICS VIEWS
CREATE OR REPLACE VIEW v_analytics_summary AS
SELECT
    COUNT(*) FILTER (WHERE state NOT IN ('RESOLVED', 'CLOSED', 'MERGED_DUPLICATE')) AS open_requests_count,
    COUNT(*) FILTER (WHERE state = 'BLOCKED_PARTS') AS blocked_by_parts_count,
    COUNT(*) FILTER (WHERE sla_breached = TRUE) AS sla_breached_count,
    ROUND(
        100.0 * COUNT(*) FILTER (WHERE sla_breached = FALSE AND state IN ('RESOLVED', 'CLOSED')) /
        NULLIF(COUNT(*) FILTER (WHERE state IN ('RESOLVED', 'CLOSED')), 0), 2
    ) AS sla_compliance_percentage
FROM work_orders;

CREATE OR REPLACE VIEW v_recurring_incidents AS
SELECT
    cn.node_code,
    cn.name AS asset_or_room_name,
    wo.category,
    COUNT(wo.id) AS incident_count_30d,
    MAX(wo.created_at) AS last_incident_at
FROM work_orders wo
JOIN campus_nodes cn ON wo.target_node_id = cn.id
WHERE wo.created_at >= NOW() - INTERVAL '30 days'
  AND wo.state <> 'MERGED_DUPLICATE'
GROUP BY cn.node_code, cn.name, wo.category
HAVING COUNT(wo.id) >= 2
ORDER BY incident_count_30d DESC;

CREATE OR REPLACE VIEW v_staff_utilization AS
SELECT
    u.id AS tech_id,
    u.full_name,
    u.is_available,
    u.active_workload_count,
    u.max_concurrent_workload,
    ROUND(100.0 * u.active_workload_count / NULLIF(u.max_concurrent_workload, 0), 1) AS utilization_pct
FROM users u
WHERE u.role = 'TECHNICIAN';

CREATE OR REPLACE VIEW v_inventory_shortages AS
SELECT
    id, sku, name, category, physical_on_hand_qty, available_qty, reserved_qty, reorder_threshold, unit_cost
FROM inventory_parts
WHERE available_qty <= reorder_threshold;

SECTION 4: BACKEND IMPLEMENTATION MODULES (FASTAPI & ASYNCPG)
================================================================================

1. DATABASE POOL SETUP (`backend/app/database.py`):
   Use `asyncpg` directly with a connection pool sized `min_size=10, max_size=50`.
   Every transaction must execute within a clean context:
   ```python
   async with pool.acquire() as conn:
       async with conn.transaction():
           ...
   ```

2. INTAKE & 4-PHASE PIPELINE (`backend/app/modules/intake/service.py`):
   - Claim idempotency key with 30s lease (`status='PROCESSING'`).
   - If key exists with different payload hash: raise HTTP 422.
   - If key exists and status == 'COMPLETED': return cached payload immediately.
   - Extract entities out-of-transaction using Pydantic:
     `IntakeExtractionSchema(category, room_hint, asset_hint, urgency, summary, safety_hazard)`
   - LLM timeout: 2.5 seconds. On timeout or error, call `deterministic_fallback_extractor(text)`.
   - Resolve `room_hint` against `campus_nodes`. If ambiguous or missing: transition to
     `AWAITING_CLARIFICATION`, store partial slots in `partial_slots` JSONB, generate question,
     and queue notification to user. Merge replies on the same `conversation_thread_id`.

3. TWO-STAGE TOPOLOGICAL CORRELATOR (`backend/app/modules/correlation/service.py`):
   - Stage A (Same Node): Check active tickets on same node. If found: increment `correlator_reporter_count`,
     link child work order with state `MERGED_DUPLICATE`, and link to master parent.
   - Stage B (Topological DAG Parent): Query `node_dependencies`. If 2 or more sibling rooms fed by the same
     upstream electrical panel, switch, or AHU report faults within 45 minutes:
     auto-create a `Master Infrastructure Incident` on the parent node, link child tickets,
     and dispatch a senior technician to the root cause node.

4. ROOM RELOCATION CSP SOLVER (`backend/app/modules/scheduling/solver.py`):
   - Hard Constraints:
     (1) `cn.node_type = 'ROOM'` and `cn.is_operational = TRUE`
     (2) `cn.room_capacity >= impacted_booking.student_count`
     (3) `cn.room_features @> impacted_booking.required_features`
     (4) No overlapping active bookings in `room_bookings` for `time_slot`
   - Soft Penalties:
     Same building (+0) vs different building (+20) + (Floor Delta * 3) + (Wasted Capacity / 10).
   - Reserve alternative via `CONTINGENCY_HOLD` status with plain-language compromise explanation.

5. TECHNICIAN DISPATCH SCORER (`backend/app/modules/staffing/service.py`):
   - Hard Filters: Role == 'TECHNICIAN', `is_available == TRUE`, matching skill in `staff_skills`,
     active workload < max capacity, current time within shift.
   - Formula:
     `Score = (SkillProficiency * 15.0) + ((1.0 - (ActiveLoad / MaxLoad)) * 25.0) + (ProximityBonus * 15.0)`
   - Dynamic Reassignment: When a technician toggles unavailable, loop over open tickets, increment
     `reassignment_count`, re-run scorer, and log handoff in `audit_logs`. If `reassignment_count >= 3`,
     escalate to Facilities Admin (anti-flap guard).

6. ATOMIC INVENTORY & APPROVAL EXECUTION (`backend/app/modules/inventory/service.py`):
   - When reserving: Lock row `SELECT ... FOR UPDATE`.
   - If `available_qty < requested_qty`:
     Update work order to `BLOCKED_PARTS`, pause SLA timer, extend room's `MAINTENANCE_BLOCK`
     by part lead time, and auto-generate an `EMERGENCY_PURCHASE` approval record with SHA-256 snapshot.
   - If stock sufficient: Insert `inventory_movements` (RESERVE), update balances atomically.
   - Approval execution (`approvals/service.py`):
     Verify Separation of Duties: `actor_id != requester_id`, `actor_id != reporter_id`, `actor_id != assigned_tech_id`.
     Verify `snapshot_hash == fn_compute_canonical_wo_snapshot(wo_id)`.
     Deduct department budget, mark approval `APPROVED`, transition work order to `APPROVED_READY`.

7. SIMULATOR (WHAT-IF ENGINE) (`backend/app/modules/simulation/service.py`):
   - Read-only dry run engine. Accepts scenario target (room, technician, switch).
   - Traverses DAG, evaluates impacted classes/exams, tests inventory stock, computes Plan A (relocation)
     and Plan B (fast repair).
   - Generates plan JSON with timestamp snapshot.
   - `POST /api/v1/simulations/{id}/execute`: Revalidates room, technician, stock, and budget constraints
     against live DB. If state changed since simulation, rejects with HTTP 409 and explains stale reason.
     If valid, executes all state changes in one atomic transaction.

8. TRANSACTIONAL OUTBOX WORKER (`backend/app/workers/outbox_worker.py`):
   - Runs every 3 seconds in a background asyncio loop.
   - Queries `SELECT * FROM outbound_notifications WHERE delivery_status = 'PENDING' AND next_retry_at <= NOW() LIMIT 20 FOR UPDATE SKIP LOCKED`.
   - Delivers to simulated webhook / log sink.
   - On success: updates `delivery_status = 'DELIVERED'`.
   - On failure: increments `attempt_count`, sets exponential backoff `2^attempt` seconds. After 5 retries,
     moves to `DEAD_LETTER`.
